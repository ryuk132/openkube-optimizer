# OpenKube Optimizer working instructions

- Purpose: compare Kubernetes CPU/memory allocations with recent utilization and explain investigation candidates for human review.
- Current gate: v0.1 freeze amended by Accepted [ADR 0008](docs/adr/0008-restricted-kubeconfig-and-bounded-transport.md) on 2026-09-30; ADRs 0001–0008 Accepted. Milestones 1 and 2 are complete; M3 architecture/design and documentation consistency are complete. M3.1 is complete; M3.2A authorizes only restricted kubeconfig document loading and direct PyYAML==6.0.3. Selection, authentication, credentials, transport, collection/projection, manifests, cluster contact and M3.2B or later slices remain unauthorized. Do not stage, commit or push.
- Follow [development setup](docs/development.md) for the approved Python 3.13.15/uv toolchain and quality checks. Direct runtime dependencies are kubernetes==36.0.3, h11==0.16.0 and PyYAML==6.0.3; SDK transitives are locked, not additional direct dependencies. Imports of OpenKube must not eagerly import them. Do not add a CLI entry point now. Create fixture files/directories only when concrete tests require them.
- Follow the [domain model](docs/domain-model.md): immutable closed facts, explicit absence/invalid/unavailable states, exact quantities, and no SDK/raw objects. AnalysisSettings and findings/evidence/report models are deferred; no collection, ownership adapter, eligibility, or rule logic belongs to Milestone 2.
- Follow the [reference-target contract](docs/compatibility.md) for selected versions, platforms, and restricted authentication. These are initial references/planned validation targets, never established runtime support. Ubuntu 24.04 LTS x86_64 with the documented resolved/procfs profile is the initial runtime validation priority; macOS is development-only. Disposable feasibility evidence is separate from foundation/domain checks and establishes no Kubernetes runtime support.
- v0.1 is one local Python CLI process, one explicit kubeconfig context, and explicitly named namespaces. No namespace discovery or in-cluster execution.
- Keep Kubernetes access read-only: only namespace-scoped `list` of Pods, Deployments, ReplicaSets, and PodMetrics. No mutation, Secrets, ConfigMaps, nodes, events, application logs, exec, attach, port-forward, proxy, token creation, impersonation, or RBAC administration. M3 is Pods/Deployments/ReplicaSets inventory; PodMetrics belongs to M4. Operator-managed RBAC setup is separate from collector behavior.
- Recommend a dedicated least-privilege identity; supplied broad credentials defeat RBAC containment. Never silently change context, widen scope, or weaken TLS verification.
- Use official generated dispatch behind controlled bounded wire validation, not stock REST errors or generated-model deserialization as the projection boundary. Unprojectable mandatory structure invalidates the namespace pass; representable uncertainty does not. Raw API objects may exist transiently only as technically required by the official client. Project immediately into the exact allowlist, release raw references promptly, and never persist, log, report, or expose raw objects through exceptions. Authentication material is transport-only. No telemetry or analytics.
- Follow [data/egress](docs/data-and-egress.md), [evidence eligibility](docs/evidence-eligibility.md), and [CLI acceptance](docs/cli-contract.md) as the field/timing/status authorities. Reports permit only necessary allowlisted resource names and are potentially sensitive. UIDs are internal memory-only for necessary analysis: never report, log, persist, or encode them into output IDs; release references promptly. No pseudonymization in v0.1.
- Follow ADR 0008 for native resolved/endpoint semantics, owned-resource cleanup, stable trusted credential files and descriptor-backed loading. Setup elapsed counts against unchanged run budgets, but synchronous file/OpenSSL parsing is not hard-cancellable; the controlled transport deadline covers DNS through HTTP. No credential copies, prompts, helper fallback or zeroization promise.
- Keep the approved ten-input configuration, closed 18-group report schema, fixed versioned evidence/operational limits, and exits 0/2/3/4/5/130. Additional internal parser/input/transport guards are versioned implementation policy, not user inputs or report fields. Additional configuration needs a demonstrated requirement not reasonably handled by the contract; additional exits need a documented reason. Review changes to the freeze before implementation; do not duplicate definitions.
- Findings are investigation candidates, never production-safe resize targets. No monetary savings, reclaimable infrastructure capacity, reliability improvement, or HIGH confidence optimization claims. Version and report thresholds; abstain when evidence is insufficient.
- Prefer simple modules, isolated I/O adapters, and pure rules. Add no services, frameworks, storage, or technologies without a concrete need and an explanation of trade-offs.
- Explain significant architectural changes before implementation and use new Proposed ADRs to supersede accepted major decisions. Keep README, architecture, security, contracts, roadmap, and ADRs consistent; distinguish accepted requirements from verified behavior.
- Use synthetic fixtures only. Test quantities, ownership, eligibility, boundary/abstention behavior, output safety, and credential/UID canary exclusion. Test API contracts and RBAC denials with a restricted identity in a disposable cluster; no production credentials or destructive production tests. Run checks appropriate to the change.
