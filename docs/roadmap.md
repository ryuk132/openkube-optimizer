## Local development choice

Propose kind with Docker on macOS for a disposable, reproducible test cluster. It gives a single environment definition suitable for later CI. Minikube remains an alternative, not a second environment we must maintain initially. Metrics Server must be installed and its TLS path configured correctly; disabling certificate verification is not the standard setup. Pin compatible versions when building this environment, then record tested versions rather than promising compatibility now.

The test operator creates synthetic Deployments and resource settings. Those administrative actions belong to test setup, never to the analysis identity. Run OpenKube locally against the disposable cluster using a separate least-privilege identity and explicit namespaces/context. Destructive tests run only in disposable clusters. No production cluster or credentials are required for development.

Prometheus and Grafana are deferred because the first release does not query historical series or expose a dashboard. The next architectural increment can introduce a Prometheus provider and a separately reviewed evidence model for historical sizing. Merely adding a provider must not enable stronger confidence claims automatically.

In-cluster execution, collector images/Jobs, token projection, runtime hardening, and NetworkPolicy are deferred to a separate architectural decision after v0.1. Automatic namespace discovery is excluded from the MVP and would require a separate scope/permission review.

## Release discipline

Basic unit tests, type checking, linting, and documentation checks begin with the package foundation. Cluster integration and security checks grow alongside the relevant code; supply-chain checks arrive before release, outside this foundation step.

The foundation uses Apache-2.0. Before publication, establish maintainers and a private vulnerability-reporting channel, document contribution expectations, and add a changelog. Do not fabricate badges, supported platforms, response commitments, adoption numbers, or performance results.

Each permission increase, new external endpoint, additional data field, or stronger recommendation claim requires review of its security and evidence implications. Feature count is not the release criterion: the agreed scope must work reproducibly and explain its limits.
